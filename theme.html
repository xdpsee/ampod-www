你也能改主题 —— AMPod 主题编写入门

这份文档假设你完全没学过编程。只要会用文本编辑器改文字，就能照着改出自己的主题。
全文用一个词固定指代 XML 里的"一种东西"：标签（尖括号包起来的名字，如 <Text>）。

怎么读这篇文章

先说清楚一件事：在 AMPod 里，一个"主题"其实就是一个文件夹，文件夹里有一张"图纸"，叫 theme.xml。 App 启动时照着这张图纸把界面摆出来——哪里放文字、哪里放按钮、按钮长什么样，全都写在图纸上。所以"改主题"这件事，说到底就是用记事本打开这张图纸，改上面的文字。改错了也不会把手机弄坏，顶多是界面变丑或者某个地方不显示了，改回来就行。

这篇文章一共 6 个部分，每章只讲一件事：第 1 章先用生活里的例子讲明白"在屏幕上摆东西"是怎么回事（位置、大小、谁套着谁）；第 2 章教你找到图纸、改图纸、看效果；第 3 章讲怎么让界面上的文字"自己会变"（比如歌名会跟着当前播放的歌换）；第 4 章讲怎么少写重复的东西；第 5 章是一本"字典"，把图纸能用的所有零件（标签）一个一个介绍给你，你不用从头读到尾，想知道某个零件怎么用，直接翻到它那一页就行；第 6 章讲图片怎么准备；最后两个附录，A 是所有可以填的"选项"速查表，B 是一个 30 分钟上手练习。

第 5 章里每个零件都写成一张统一的"卡片"，卡片一共 6 栏，长得像这样（下面只是一个图例，演示每一栏是干什么的，真正的卡片内容在后续章节里）：

### <中文名> `<标签>` —— 一句大白话用途
**长这样：** (ASCII 框图或"见某主题第N行")
**照抄能跑：** 一行最小 XML
**常用属性：** 表格(属性 | 怎么写 | 大白话作用)
**更多属性：** 一行带过 → 见附录 A
**小白坑：** 最易错的一处

读卡片的方法：先看"长这样"，知道这个零件在屏幕上是什么效果；再看"照抄能跑"，那一行 XML 你可以原样复制进自己的图纸，立刻能看到东西出现；然后看"常用属性"表，表里每一行是一个可以填的"选项"——比如下面图例里只示意的两行：

属性 怎么写 大白话作用
text text="你好" 写上要显示的文字
color color="#FF0000" 文字颜色，红绿蓝各两位
（这里只是举例怎么读表，<Text> 的完整属性细节见 5.1。）最后一栏"小白坑"提醒你新手最容易犯的一个错，抄代码前扫一眼能省很多折腾。

第 1 章 先搞懂"摆东西" —— 布局(Layout)

在正式改图纸之前，先把一件事想明白：界面就是把一堆东西摆到屏幕上。一块文字、一张封面图、一个按钮——每一个都得回答两个问题：摆在哪儿？多大？

在图纸里，回答这两个问题的东西叫 Layout（读音"雷奥特"，意思是"布局"，就是"摆放方案"）。图纸上每个组件标签里面，都藏着一个小跟班 <Layout/> 标签，专门写它的摆放方案。你可以把组件想成一个相框：相框里装什么照片是组件自己的事，而相框钉在墙上哪个位置、相框多大，全由 <Layout/> 说了算。

1.1 屏幕就是一面墙：八个"图钉孔"

<Layout/> 能用的位置写法一共只有 8 个，别多也别少。想象屏幕是一个盒子，每个组件也是一个小盒子，被放进大盒子里。小盒子在大盒子里怎么定位，就靠这 8 个"图钉孔"：

             top
              ↓
   left → ┌───────────────────┐ ← right
          │                   │
          │    ┌─────────┐    │
          │    │  组件   │    │
          │    │    ·    │    │
          │    └─────────┘    │
          │                   │
  bottom →└───────────────────┘
          ←───── width ─────→      height = 框自己多高

   · 是组件的中心点。
   left / right / top / bottom：决定这个框贴靠哪条边。
   centerX / centerY：让 · 对准整面墙的竖直中线 / 水平中线，用来居中。
图钉孔(真实写法) 大白话
left 靠左：小盒子的左边对齐到哪
right 靠右：小盒子的右边对齐到哪
top 靠上：小盒子的上边对齐到哪
bottom 靠下：小盒子的下边对齐到哪
centerX 水平居中：小盒子的中线对准哪条竖线
centerY 垂直居中：小盒子的中线对准哪条横线
width 自己多宽
height 自己多高

1.2 等号右边填什么：装着我的盒子、整个屏幕、别的组件、纯数字

图钉孔找到了，还得说清楚"对齐到哪儿"——也就是等号右边引号里填的东西。一共四类：

第一类：parent——"装着我的那个盒子"。 组件都是层层套放的，parent（读音"派恩特"，意思是"家长、外面那层"）就是指套着自己的最近那层：外面有收纳盒就指那个盒、被抽屉队装着就指那条抽屉，最外层没套东西时就指整个屏幕。比如：

<Layout left="parent.left+20" top="parent.top" right="parent.right-20" bottom="parent.bottom"/>

这一行是真的（出自 Simple 主题图纸）：左边往里挪 20、右边往里挪 20、上下贴边——效果就是"铺满整块地方，但左右各留一条 20 宽的缝"。+20 就是"再往里挪 20"，-20 就是"再退回来 20"，跟算账一样。

第二类：screen——"整个屏幕，不管被几层盒子套着"。 screen（屏幕）和 parent 一样能写 .left .right .top .bottom .centerX .centerY，区别在于它永远指整个屏幕，不像 parent 会被最近的盒子改口。什么时候用它？想让一块东西顶天立地贴屏幕两边、不受盒子内缩影响的时候——比如播放页顶上的导航条、底部整条状态色带。真实例子（Simple 图纸第 58 行）：

<Layout left="screen.left" top="screen.top" right="screen.right" bottom="parent.top+100"/>

翻译：左右贴屏幕、上边贴屏幕顶、下边再参照父盒子往下挪 100——一句话里 parent 和 screen 可以混着用。新手记一句就够：想跟着盒走用 parent，想钉死在屏幕上用 screen。

第三类：#它的名字——"挂在某个组件旁边"。 图纸上的组件都可以起个名字（写在其 id 属性里，类似给东西贴个名牌）。#cover.bottom+8 这种写法的意思是："id 叫 cover 那个组件的底边，再往下 8"——就像"把说明牌挂在这张封面照片下面，留 8 的空隙"。真实样本：

<Layout centerY="#albumCover.centerY" left="#albumCover.right+10" width="180"/>

翻译：垂直方向跟封面图对齐在同一高度，水平方向贴在封面图右边缘再往右 10，自己宽 180。（"跟封面并排站、中间留点缝的文字块"，就是它。）

第四类：直接给数字。 width="80" 就是宽 80。数字是"点"（diǎn，屏幕上量长度的单位，约等于一个小米粒），手机上 80 点大概是指甲盖宽度。位置数字也可以是负数（比如 top="-12"，意思"往上冒出去 12"，常用来让东西故意压线）；但 width 和 height 必须大于 0，写 0 或负数等于没写，东西会被忽略掉。

还有一个特殊词：auto（自动）。 width="auto" 意思是"我多宽由我的内容说了算"——比如一块文字，写"你好"就短，写"正在播放的歌曲名称很长"就长，auto 就是让它自己按字数伸缩，不用你操心。真实样本：

<Layout centerY="#buttonPlay.centerY" centerX="#buttonPlay.centerX" width="auto" height="auto"/>

翻译：这块东西（自动大小）的中心对准播放按钮的中心——就是"正好叠在播放按钮正中间的一小段字"。

1.3 谁盖着谁：zOrder(叠放次序)

两个东西摆到了同一块地方，谁在上面盖着谁？图纸用一个叫 zOrder（读音"Z-奥德尔"，意思是"叠放次序"）的数字决定：数字大的盖在数字小的上面，就像叠扑克牌。两个东西数字相同（或者都没写，没写就当作 0），就按图纸里写的先后——后写的盖在上面。所以想让某个东西永远不被盖住，给它写个大的 zOrder（比如 zOrder="10"）就行。

1.4 一个完整的小例子

下面这两行合起来就是"一块文字，摆在哪、多大"的完整写法（照此格式写，放到真实图纸里就能用）：

<Text id="title" text="正在播放" ...>
    <Layout left="parent.left+20" right="parent.right-20" centerY="parent.centerY" height="40"/>
</Text>

它在屏幕上长这样：

┌──────────────────────────────┐
│                              │  ← 整个屏幕 / 盒子
│      ┌────────────────────┐  │
│      │      正在播放      │  │  ← 这块卡片 height = 40
│      └────────────────────┘  │     left / right 各收 20
│                              │     centerY 让它上下居中
└──────────────────────────────┘

读图口诀：先找参照物（parent 装着我的盒 / screen 整个屏幕 / #名字 别的组件），再看偏移（+几、-几），最后看大小（width/height，或 auto）。三样凑齐，摆放就说得明明白白。

1.5 三种"打包摆法"先混个脸熟

东西一多，一个个算坐标会累死人。图纸还提供了三种"打包摆放"的容器（容器=能装别的组件的大盒子），先建立印象，这一章不用会写：

  • Box（盒子）：一个透明收纳盒，盒里的东西都按"盒子的边"定位。挪一下盒子，盒里的东西整体跟着挪——适合"一组永远一起动的东西"。
  • Stack（一摞）：自动排队的抽屉。东西丢进去，它自动帮你排齐、自动留缝，不用自己算任何坐标——适合一列按钮、一行菜单。
  • Scroll（翻页相册）：左右（或上下）能翻页的相册，一屏一页，手指一划就换页——适合"好几页内容轮着看"。
这三种的完整用法，分别在第 4 章和第 5.3 节里细讲，这里知道"有它们、大概是干嘛的"就够了。

第 2 章 主题就是一个文件夹 + 一张图纸

这一章解决三个问题：主题文件在电脑上的哪里、图纸 theme.xml 长什么骨架、改完之后怎么让 App 用上它。

2.1 先找到"主题"这个东西

打开项目的 AMPod/Themes/ 文件夹，你会看到一排子文件夹：Black、White、Classic、CoverFlow、Vinyl、Simple、Simple(White)、暗夜星空……每一个文件夹就是一个主题，文件夹名就是主题名。

随便点开一个（比如 Simple），里面只有两样东西：

  • 一张主图纸：theme.xml，用任何记事本都能打开、能改；
  • 一堆图片：如 eAlbumCover@3x.png、ePlayS@3x.png（.png 是最常见的图片格式）。图纸里写"这里放封面图"，放的就是这些图片。图片的完整命名规矩在第 6 章细讲，这章只要知道"图纸管摆法、图片管长相"就够了。
所以"做一个自己的主题"的完整操作就是：把整个文件夹复制一份、改个名（比如复制 Simple 改成 MySimple），然后放心大胆地改新文件夹里的图纸和图——原来的主题一个字节都不会动，改坏了随时删掉重来。

2.2 图纸 theme.xml 的骨架：三大块

别看 theme.xml 有一千六百多行，其实反复出现的只是三大块"章节"，每块管一类事：

第一块：<Common>——全主题共用的"字帖"。 开头几行原样长这样（出自 Simple 图纸第 4~6 行）：

<Common>
    <Style value="dark"/>
    <Font id="titleFont" family="PingFangSC_Reguar" size="20"/>

<Style> 定的是整体明暗基调（dark = 深色），<Font> 是"字帖"：给一种字体起个名字（id），写清楚字体和字号。之后图纸上任何一块文字只要报这个字帖的名字（fontRef="#titleFont"），就直接用上这套字体字号——就像公司统一公文模板，改一次模板，全公司的文件跟着变。想全局换字体、改字号，改这一块最省力。

第二块：<TabBar>——手机屏幕底部那排标签按钮。 Simple 图纸第 21~27 行原样：

<TabBar backgroundColor="#00000000" textColor="#a0a0a0" selectedTextColor="#f0f0f0" iconColor="#a0a0a0" selectedIconColor="#f0f0f0">
    <Medias icon="eTabMedias"/>
    <Playlists icon="eTabPlaylists"/>
    <Folders icon="eTabFolders"/>
    <Library icon="eTabLibrary"/>
    <More icon="eTabMore"/>
</TabBar>

<Medias>、<Playlists> 这些标签各代表底部一个标签页（媒体、歌单、文件夹、资料库、更多），icon= 后面写的是图标图片的文件名（不带 .png 后缀）。想换底部图标，把对应图片换成自己的就行。

第三块：<Page>——App 里每一屏各有一张图纸。 第 1 章讲的组件（<Text>、<Image>、<IconButton>……）全都写在 <Page> 里。每个 <Page> 有个 id 名字，对应 App 的一屏，比如：

<Page id="MiniPlayer" height="48" backgroundColor="#00000000" dynamicBackground="false" popupBarTransparent="true">

这就是屏幕底部那条"迷你播放条"（5.6 节会讲它的完整长相）。Albums 那一屏的图纸就是 <Page id="Albums" ...>、More 那一屏就是 <Page id="More" ...>。想改哪一屏，就找到 id 是它名字的那一段改。 顺带认脸：<Page id="More">（"更多"屏）里列着"主题 / 设置 / 关于 / WiFi 传文件"这些入口，其中"主题"入口就是 2.4 节要用的切换页。

图纸上还会零星看到 <Actions>，它是工具条里的"一键操作"小组（比如批量删除、加入歌单），藏在某屏的工具条里面，不是独立大块，这里混个脸熟即可。

2.3 一个主题其实有 50 多张图纸：语言与尺寸"变体"

再仔细看一眼 Simple 文件夹，会发现 xml 文件不止一个——有 54 个！命名规律是：

  • 基础图纸 theme.xml：内容是中文。
  • 其他语言 = 文件名里加语言码：theme.en.xml（英语）、theme.de.xml（德语）、theme.fr.xml（法语）、theme.ja.xml（日语）、theme.ko.xml（韩语），Simple 主题还有 theme.yue-Hant.xml（粤语）、theme.zh-Hans.xml（简体中文）、theme.zh-Hant.xml（繁体中文）。语言码就是 App/手机设置里那套语言的代号。
  • 每种语言再按屏幕分尺寸：theme.en@320x568.xml、theme.en@375x667.xml、theme.en@414x736.xml（@数字x数字 是手机屏幕分辨率），外加 theme.en@iPad.xml（平板）和 theme.en@Duo.xml（折叠屏）。
所以每种语言有 6 个"档位"：通用版 + 3 个手机尺寸版 + iPad 版 + Duo 版。语言 × 档位，凑出这 54 个文件。

App 怎么挑图纸？像点餐一样逐级退省：

  1. 先看有没有"你的语言 + 你的尺寸"那张——手机是英文、屏幕 375x667，就点 theme.en@375x667.xml；
  2. 没有这一档？退而点"你的语言"的通用款——theme.en.xml；
  3. 连语言款都没有？退到基础款 theme.xml（中文）。
这条规则对改主题最重要的影响：改一处，常要同步改多个文件。 比如你把主图纸 theme.xml 里一句话改了，可英文手机上显示的是 theme.en 系列图纸里的旧句子——那边纹丝不动；反过来中文用户可能走的是 theme.zh-Hans@375x667.xml，主图纸改了他也看不见。自己用哪几种语言、哪几档屏幕，就把那几个对应文件一起改，其余可以不管。

好消息：某个变体文件缺失不会弄坏界面——App 自动退回上一档，顶多文字变回中文。但如果某个变体文件存在、里面却写错了，那一档就真的白屏，不会替你退档。

2.4 怎么让 App 用上你的主题

三步：

  1. 复制一个主题文件夹，改成你喜欢的名字（如 MySimple），放回 AMPod/Themes/ 里、和官方主题们并排放好；重新编译安装运行 App 后，App 会自动把它认成一个新主题；
  2. 打开 App，进"更多"页 → 点"主题"；
  3. 在列表里选中你的主题，界面立刻换成你的。
改坏了也不怕：随时切回别的主题，你的文件夹只是躺在硬盘里，不动别人的。

2.5 改完怎么验证生效

  • 一次只改一小处，改一次看一次。 别一口气改二十行——真出了问题是哪一行的锅就找不出了。改一行、保存、重新打开 App 看效果，是最省时间的节奏。
  • 界面是"容错"的：改坏了不会让 App 打不开或闪退，最常见的坏法是那一块干脆不显示、那一屏空白、或者画面退回你没改的样子。看到这种"它装没看见"，就是图纸某处写错了的信号，回头检查刚才那一小处——新手最高发的是：标签没合上（<Text ...> 写了却忘了配套的 </Text>）、属性引号漏了一边（写成 text=你好）。
  • 整个界面一点变化都没有？ 十有八九是 App 里没选中你的主题，或者你改的文件不是当前语言/尺寸正在用的那个变体（回到 2.3 的"点餐"规则对一对）。
  • 实在找不到北，就把这次改动撤销回去看效果回不回得来：回来了，说明问题就出在刚才那一行。

第 3 章 让文字"自己会变" —— 数据绑定与动作

前两章里，图纸上的东西都是"写死的"：<Text> 里写"你好"，屏幕上就一直显示"你好"。可播放界面不一样——歌名要跟着当前播放的歌换、进度条要一秒一秒往前走、封面图要换成这张歌自己的封面。这一章讲的就是怎么给组件"接根水管"，让 App 里的实时数据自动流进来，以及另一半孪生问题：你点一下按钮，怎么让 App 去干活。

3.1 数据绑定 subscribe —— 给组件接根水管

组件默认是"死"的，要让它跟着播放状态自动变，就在它的标签上加一个 subscribe（读音"瑟斯凯布"，意思是"订阅"）属性。订阅的写法固定是一个等号加引号，引号里分成两半，中间用一个冒号隔开：

subscribe="要改组件的哪个部位:${数据的名字}"

冒号左边是"水管接到组件的哪个接口上"（显示的文字？图片？藏不藏起来？），冒号右边 :${...} 里是"数据的水源叫什么名字"。举几个 Simple 主题里的真实写法：

  • subscribe="text:${media.title}" —— 把这块文字的内容接到"当前歌曲标题"上，换歌时它自己跟着变（图纸第 39 行）。
  • subscribe="text:${media.artist}" —— 接到歌手名上（第 1081 行）。
  • subscribe="text:${media.duration}" —— 接到"这首歌总时长"上，就是进度条旁边那个 04:34（第 1141 行）。
  • subscribe="image:${media.artwork}" —— 把图片组件接到"当前封面图"上，换歌封面跟着换（第 35 行）。
  • subscribe="hidden:${playback.state.playing}" —— "正在播放"这个状态一旦为真就把组件藏起来；暂停时它又冒出来。播放按钮就是这么做到"只在暂停时出现"的（第 46 行）。它的反面是 visible:：正在播放时才显示，给暂停按钮用（第 50 行）。
  • subscribe="select:${media.favorited}" —— 接到"当前歌是否已收藏"上，决定收藏按钮亮还是不亮（第 1088 行）。
  • subscribe="select:${playback.shuffle}" —— 接到"随机播放开没开"上（第 1155 行）。
  • subscribe="enable:${transform.wifi.opened}" —— 接到"WiFi 传文件开了没"上，没开就把按钮变成点不动的灰的（第 1393 行）。
一个组件可以同时接好几根水管，用分号 ; 隔开（程序里就是按分号拆开一根根处理的）。比如黑胶主题里那张转盘，一行同时接了三根（Vinyl 主题真实写法）： 
subscribe="enable:${playback.state.playing};image:${media.artwork};value:${media.progress}"

意思是：正在播放才转动、封面用当前歌的、转到的位置跟着播放进度走。

3.2 动作命令 onClick —— 点一下喊一嗓子

水管管的是"数据流向屏幕"，反方向——"你的点击传给 App"——靠按钮类标签上的 onClick（读音"昂克立克"，意思是"被点击时"）属性。它填的不是数据，而是一条命令：一个短横线连着的小写词，比如 onClick="playback-start"。你点下去，这串词就一层层往上传给 App 的总调度（App 里管这事的"服务台"叫 AppExecutor）；服务台听懂哪个词，就去干对应的活——开始播放、切下一首、打开搜索……

注意：onClick 不是每个组件都有，只有按钮类的才有（<IconButton>、<ToggleButton>、<TextIconButton>、<SwitchButton>……第 5 章的卡片会逐个标清楚谁认什么）。

小白坑

命令词表远不止上面这十几个（还有 router-back 返回上一页、schema-medias-play-all 播放全部等等），但你不用背、也不用穷举——新手改主题时最常用的招是"把现成的按钮挪位置、改样子"，原来的 onClick 是什么就沿用什么，这是最安全的。真要加新命令，先在现成主题图纸里搜同样的词，看人家挂在什么组件上，照着挂；挂在认不得这个命令的组件上，点了就石沉大海。命令后面能不能带参数、哪些组件认哪些命令，第 5 章各按钮卡片里会讲。

3.3 小结

subscribe 是把 App 的实时数据接进组件的水管（部位:${数据名}，写错不报错、只是不变）；onClick 是点按钮时喊给服务台的一嗓子（一条短横线小写词）。一进一出，界面就"活"了。

第 4 章 少写重复 —— Box / Stack / 模板(Include)

第 1 章末尾说过：东西一多，一个个算坐标会累死人。这一章把三种"打包摆法"里的两样——收纳盒（Box）和自动排队的抽屉（Stack）——完整讲给你，再介绍第三样复用利器：复印机（模板 / Include）。（"翻页相册"Scroll 属于页面级组件，它的用法在 5.3 节单讲。）

4.1 Box —— 透明收纳盒

Box（意思是"盒子"）是一个透明收纳盒：把一组组件装进去，盒里每个组件的 parent（第 1 章学的"外面那层"）指的就是这个盒子本身。想挪动这一整组？只挪盒子，盒里全部跟着动，不用改里面的任何一行坐标。盒子还可以顺便化个妆：填色、圆角、描边、毛玻璃。

Simple 主题图纸里就有真的 Box，第 1069~1091 行原样如下（缩进略作收拾）。它是播放页那个能左右翻的"相册"的第一页，装着封面、频谱条、歌名、歌手和两个小按钮：

<Box>
    <Image id="albumCover" zOrder="2" defaultImage="eAlbumCover" borderColor="#ffffff20" borderWidth="0.5"
           cornerRadius="16" shadowColor="#000000" shadowOffset="{8,8}" shadowOpacity="0.2" shadowRadius="12"
           subscribe="image:${media.artwork}">
        <Layout top="parent.top+48" left="parent.left+32" right="parent.right-32" height="#albumCover.width@999"/>
    </Image>
    <SpectrumView id="spectrumView" zOrder="3" bins="80" gaps="1" gradientStartColor="#ffffff" gradientEndColor="#a0a0a0">
        <Layout left="parent.left+32" top="#albumCover.bottom" right="parent.right-32" height="120"/>
    </SpectrumView>
    <Text id="textTitle" zOrder="4" marquee="true" fontRef="#STHeitiSC-Medium-18" textColor="#e0e0e0" textAlignment="left" subscribe="text:${media.title}">
        <Layout left="parent.left+32" top="#spectrumView.bottom-16" right="#btnFavorite.left-32"/>
    </Text>
    <Text id="textArtist" zOrder="4" marquee="true" fontRef="#STHeitiSC-Medium-18" textColor="#e0e0e0" textAlignment="left" subscribe="text:${media.artist}">
        <Layout left="#textTitle.left" top="#textTitle.bottom" right="#textTitle.right"/>
    </Text>
    <IconButton id="btnQueue" zOrder="4" imageNormal="eQueue" onClick="media-queue-open">
        <Layout centerY="#textTitle.centerY" right="#albumCover.right" width="24" height="24"/>
    </IconButton>
    <ToggleButton id="btnFavorite" zOrder="4" imageSelected="eFavMark" imageUnselected="eFavUnmark"
        onClick="media-favorite-toggle" subscribe="select:${media.favorited}">
        <Layout centerY="#btnQueue.centerY" right="#btnQueue.left-32" width="24" height="24"/>
    </ToggleButton>
</Box>

逐处认一下重点：

  • 这个 <Box> 自己没写 <Layout>——因为它当的是相册的一页，整页铺满，位置由相册给。平时你手写 Box 时，盒子和普通组件一样要挂自己的 <Layout>。
  • 盒里的 <Layout> 写的 parent.top+48、parent.left+32——这个 parent 是盒子，不是屏幕。封面离"盒顶"48、离"盒左边"32。
  • 封面的 height="#albumCover.width@999" 是"高度照自己的宽度来"，即正方形（@999 是个"硬度"数字，先不用管，照抄就行）。
  • 歌名、歌手、两个按钮之间互相用 #名牌 牵着排（第 1 章学过），整组都在同一个盒里——这就是一组"永远一起动的东西"。
Box 支持的属性一共 8 个（... 表示可写可不写）：
属性 怎么写 大白话作用
id id="card" 贴名牌；写了别的组件才能挂它（如 #card.bottom）
zOrder zOrder="3" 叠放次序，1.3 学过
fillColor fillColor="#22000000" 盒底填的颜色。# 后 8 位：前 6 位颜色、后 2 位透明度（00 全透明、FF 一点不透）
cornerRadius cornerRadius="16" 圆角，数字越大角越圆
clip clip="true"（或 1） 超出盒子边的内容剪掉，不让它探出盒外
borderColor borderColor="#33ffffff" 描边（边框）的颜色；必须和下面那个一起写才生效
borderWidth borderWidth="0.5" 描边的粗细
blur blur="dark" 或 "light" 盒底垫一层毛玻璃（半透明磨砂质感，分深、浅两种）
要说明的是：现成主题里仅有的这些 Box 全是不带任何外观的透明盒（它们都是相册的页面）。带底色、圆角的 Box 暂无现成示例，下面这个是最小示意——按上表真实存在的属性拼的，可以照格式写，但用前务必先在主题副本上验证（2.1 教过怎么复制）： 
<Box id="card" fillColor="#22000000" cornerRadius="12" clip="true">
    <Layout left="parent.left+16" right="parent.right-16" top="parent.top+60" height="92"/>
    <!-- 盒里照常放组件，它们的 parent 就是这个盒 -->
</Box>

（一张左右各收 16、离顶 60、高 92 的半透明黑圆角卡片。）

小白坑

一旦组件被装进盒子，它 <Layout> 里的 parent 就从"屏幕"改口叫"盒子"了（想让盒里某样东西仍然贴着屏幕、不受盒子内缩影响，就改用 screen，见 1.2）。新手最常见的翻车：把原本按屏幕摆好的一组组件原样套进一个 Box 里，里面一个坐标都没动，位置却全变了——因为参照物换成了盒子的边。所以先定盒子的大小位置，再按"盒就是世界"写盒里的东西。另外，盒子自己尽量把大小说清楚（横着给 left+right 或 width，竖着给 top+bottom 或 height），完全靠内容撑开的盒子容易和你想的不一样。

4.2 Stack —— 自动排队的抽屉

Stack（意思是"一摞"）就是第 1 章说的自动排队的抽屉：组件丢进去，抽屉按你定的方向（横排或竖排）照书写的先后顺序把它们排成一队、自动留缝——队里每个组件不用写任何坐标。Black、White、Classic、CoverFlow、Vinyl、Simple、暗夜星空这些主题里到处都是它。

真实样本——Simple 图纸第 1145~1156 行，播放界面最底下那一排 6 个按钮（循环模式、上一首、播放、暂停、下一首、随机）：

<Stack id="stackControls" zOrder="2" direction="horizontal" distribute="equalSpacing" align="centerY">
    <Layout left="parent.left+32" right="parent.right-32" bottom="parent.bottom"/>
    <PlayModeButton imageNormal="eNormal" imageRepeatAll="eRepeatAll"
                    imageRepeatOne="eRepeat1" imageShuffle="eShuffle"
                    onClick="playback-switch-mode" subscribe="value:${playback.mode}"/>
    <IconButton imageNormal="eBackward" onClick="playback-backward"/>
    <IconButton imageNormal="ePlay" onClick="playback-start" subscribe="hidden:${playback.state.playing}"/>
    <IconButton imageNormal="ePause" onClick="playback-pause" subscribe="visible:${playback.state.playing}"/>
    <IconButton imageNormal="eForward" onClick="playback-forward"/>
    <ToggleButton imageSelected="eShuffleOn" imageUnselected="eShuffleOff"
        onClick="playback-switch-shuffle" subscribe="select:${playback.shuffle}"/>
</Stack>

看门道：只有抽屉自己写了 <Layout>（贴屏幕底边、左右各收 32），队里 6 个按钮一个坐标都没有。direction="horizontal" 是横排；distribute="equalSpacing" 把它们均匀铺满一整行；align="centerY" 让高矮不一的按钮在竖直方向对齐居中。想给这排按钮换个顺序？把两行 XML 挪个位置就行，不用重算任何坐标。

抽屉可用的属性：

属性 怎么写 大白话作用
direction direction="horizontal" 排队方向：horizontal 横排 / vertical 竖排（不写默认竖排）
distribute distribute="equalSpacing" 一整队怎么分空间，5 选 1，见下表
align align="centerY"（或 center） 交叉方向怎么对齐，见下表
spacing spacing="12" 相邻两个之间的缝有多宽（数字）
padding padding="8,12,8,12" 抽屉内侧四周再留一圈空：逗号隔开四个数，依次是左,上,右,下
distribute（分布）的 5 个值：
值 大白话
fill（默认，不写就是它） 从队头一个个往队尾码，每个保持自己的大小，缝按 spacing，富余空间全堆在队尾——"从抽屉一头开始摆东西"
fillEqually 整块地方平均分给每一个，大家一样大——"切格子"
fillProportionally 按各自身上内容的大小比例分，内容大的多占点地方
equalSpacing 头一个贴最左（或最上）、末一个贴最右（或最下），中间的缝全一样宽——工具栏"铺满一整行"首选
equalCentering 也首尾贴边，但保证每个的"中心点"隔得一样开；队里东西宽窄不一时看着更整齐
后四种要吃掉"富余空间"才显出效果，所以抽屉自己必须先占满一整块地（横排把 left+right 都写全，竖排把 top+bottom 都写全），否则缝会塌回去。

align（对齐）对照表：

align 竖排时（管左右） 横排时（管上下）
start（默认） 靠左 靠上
center（写 centerX/centerY 也认） 水平居中 垂直居中（最常用）
end 靠右 靠下

Stack 铁律（重点，背下来）

抽屉里的组件，关于 <Layout> 只有两种合法写法：

  1. 干脆不写 <Layout>——推荐，也是上面真实样本的做法：按钮多大由图片决定、文字多长由内容决定；
  2. 写，但只准写 width 和/或 height，值只能是数字（后面可跟 @数字 表示硬度，不跟也行）或 auto。例如 <Layout width="44" height="44"/>。
除此之外，在队里组件的 <Layout> 里写 left right top bottom centerX centerY 这些定位，或者写 #谁谁谁 这种引用——整屏直接加载失败、变成空白。记住那句话：排队归抽屉管，坐标轮不到你写。同理，抽屉里不能再装 Box、Stack 或模板（装了同样判违规、整屏挂掉）——要分组，在抽屉外面分。队里的组件倒是照常可以贴名牌 id，屏上别的地方能用 #它的id 挂它。

竖排抽屉暂无现成示例（现成主题里用到的 Stack 全是横排按钮行），下面是据真实属性拼的最小示意——一列文字加按钮排下来：

<Stack direction="vertical" spacing="6" align="center">
    <Layout left="parent.left+20" top="parent.top+40" width="200"/>
    <Text textValue="标题"/>
    <Text textValue="副标题"/>
    <IconButton imageNormal="ePlay" onClick="playback-start"/>
</Stack>

（一条宽 200、起点离顶 40 的竖抽屉；里面三样从上到下按书写顺序排，每个之间留 6 的缝，都水平居中。）

小白坑

用了 equalSpacing 之类的分布，却发现按钮全挤成一坨、缝没了？十有八九是抽屉自己没占地盘——横排只写了 bottom 没写 left/right，抽屉收到刚够装下按钮的宽度，没有富余空间可均分。给抽屉自己的 <Layout> 补上 left + right（横排）或 top + bottom（竖排）就好。

4.3 Include —— 复印机（模板）

改主题改到一定规模你会发现：好几屏都有一模一样的一条导航栏。一行行复印，改一处就得跑五个地方改五遍。引擎为此提供了"复印机"：图纸开头用 <Define>（意思是"定义"）画一段样板，之后哪一屏要用，就 <Include ref="样板名">（Include，意思是"纳入"）复印一份出来。样板改一处，所有复印件跟着变；样板上还能留"填空" {{...}}，每份复印时填不同的值。

先说现状：实测所有现成主题里 Include / Define 的使用次数是 0——引擎支持、也有专业文档（docs/theme-nesting-usage.md），但没有任何现成活例子。所以这一小节只给"据语法拼的最小示意"，不是成品抄了就跑。新手先用 4.1 / 4.2 就够；决定上复印机时，务必先在主题副本上试（2.1 教过复制），每一屏都检查过再用到正式图纸上。

示意（结构、属性名都是引擎真实认的，内容是为讲解拼的）：

<!-- ① 图纸开头、和 <Page> 平级的位置，先画样板 -->
<Defines>
    <Define id="navbar">
        <Text id="title" textValue="{{title}}">
            <Layout centerX="parent.centerX" top="parent.top+12"/>
        </Text>
    </Define>
</Defines>

<!-- ② 哪一屏要，就复印一次，顺便填空 -->
<Page id="Albums">
    <Include id="nav" ref="navbar" title="专辑">
        <Layout left="parent.left" top="parent.top" right="parent.right" height="56"/>
    </Include>
</Page>

逐处认一下：

  • 样板的名字是 navbar，里面 {{title}} 是一个填空。
  • ref="navbar" 说清复印哪份样板；id="nav" 必需——这次复印品的名字。复印完成后，样板里的组件会自动挂上"复印件名/"做前缀（上面的文字就变成叫 nav/title 了），所以同一份样板复印一百次也互不打架；屏上其他组件能挂这张复印件整体（#nav.bottom），也能挂它内部的（#nav/title.top）。
  • 多出来的那个 title="专辑" 就是填进 {{title}} 空的值：这一屏显示"专辑"，另一屏复印时写 title="艺术家" 就显示"艺术家"。
  • Include 自己的 <Layout> 决定这份复印件贴在屏上哪里——样板不管自己被贴去哪。
规矩（破坏任何一条，和 Box/Stack 的错一样：整屏不加载）：
  • 填空 {{...}} 只能出现在"显示类"属性里（文字、颜色、图片名、字号这些）；写进 onClick 或 subscribe 不行——命令和水管（第 3 章）必须每屏自己明着写。
  • 样板里面不能再套复印（<Define> 里不许出现 <Include>）。
  • ref 的样板名拼错、或样板留了空而你没填齐，直接报错挂掉整屏。

4.4 三样配合起来用

一句话分工：收纳盒（Box）管"整块一起动"——一组永远一起动的东西装进盒，以后只挪盒；抽屉（Stack）管"同类的排一队"——一行按钮丢进去，队内一个坐标都不用写；复印机（Include）管"同一段印 N 份"——样板画一次，到处复印。它们还常常叠着用：外面 Box 定位置，盒里 Stack 排一排按钮；而一份 Include 样板里，本身就可以装着 Box 或 Stack。目的只有一个——少写重复、改一处全变。

5.1 基础显示

本节 5 张卡：文字、文本框、图片、小图标、矩形板——都是屏幕上"纯显示"的零件，画什么看到什么。第 3 章教的水管（subscribe）它们里有三样能接（文字、图片、小图标），矩形板和文本框不接。每卡的"照抄能跑"都记得带上 <Layout/> 小跟班（第 1 章的老规矩：不写摆放，整屏不显示）。

文字 <Text> —— 在屏幕上显示一块字

长这样： 一行（或多行）字。播放页的歌名、歌手名，列表里的条目文字，全是它。真实例子见 Simple 图纸第 1078、1081 行——上下叠着的歌名和歌手两行字（第 4 章装盒那段里就出现过）。

照抄能跑： 屏幕正中一句写死的字（属性都是引擎认的；接了水管"跟着换歌自动变"的写法，第 3 章 3.1 已经给过）：

<Text id="hello" fontSize="20" textColor="#ffffff" textValue="你好">

</Text>

文本框 <TextView> —— 可多行、能点进去打字的文本框

⚠️ 先泼冷水：引擎支持这个标签，但实测所有现成主题里 0 次引用——Black、White、Classic、CoverFlow、Vinyl、Simple、暗夜星空没有任何一个用过 <TextView>，没有活例子。照抄后务必先在主题副本上验证效果（2.1 教过怎么复制），确认没问题再写进正式图纸。

5.2 按钮与交互

本节 11 张卡：从最普通的带字按钮，到图片按钮、开关、滑条、搜索框——都是"能跟手指打交道"的零件。第 3 章教的"喊一嗓子"（onClick）大部分卡都有，但有两个例外：拨动开关用 onStateOn/onStateOff、弹出菜单按钮用 command（卡片里会专门讲）；而最后的搜索框是输入框，根本没有点击命令。"接水管"（subscribe）它们几乎全都支持。老规矩：每卡的"照抄能跑"都带着 <Layout/> 小跟班。

5.3 容器与布局

本节 5 张卡。前三张 Box、Stack、Include 第 4 章已完整讲过（收纳盒、抽屉、复印机的比喻和全例都在那），这里只压缩成速查卡——"这标签到底能写哪些属性"一张表看全，讲透的部分回指 4.1 / 4.2 / 4.3；后两张 Scroll、Toolbar 是新面孔，完整展开。一条通用纪律先说在前头：水管（subscribe）不接容器——写在 Box / Stack / Scroll 上会被引擎无视（还会记一行日志）；工具条 Toolbar 是个例外，它接水管的写法跟别人不一样，见它的卡。老规矩：每卡"照抄能跑"都带 <Layout/> 小跟班。

收纳盒 <Box> —— 一组永远一起动的东西（速查）

长这样： 透明收纳盒——第 4 章 4.1 全讲过：装进去的组件互相以盒为 parent，挪盒整组跟着挪；顺便还能填色、圆角、描边、毛玻璃。活例子是 Simple 图纸第 1069~1091 行（播放页相册的一页，4.1 开头贴的就是它原文）。

    <Layout left="parent.left+16" right="parent.right-16" top="parent.top+60" height="92"/>

</Box>

小白坑： 最大的规矩：相册的每一页必须是一个 <Box>。往 <Scroll> 里直接摆 Text、Image 这类散组件（没装盒），整屏直接加载失败——引擎只收 <Box> 当页，没有通融（第 1 章 1.5 说过"一页=一个盒"，这里是引擎强制的硬纪律）。空相册（一个盒都没有）不报错，但就是一片空白。还有：它的 direction 默认和抽屉相反——抽屉不写默认竖、相册不写默认横，照抄时把 direction 明写出来最稳。

属性 怎么写 大白话作用

复印机 <Include> —— 抄样板印一份（速查，现成主题无活例）

⚠️ 现状回指 4.3：实测所有现成主题 Include / Define 使用次数为 0——引擎支持、专业文档齐全（docs/theme-nesting-usage.md），但没有任何活例子。新手先用 Box/Stack 就够；决定上复印机，务必先照 2.1 复制主题副本、逐屏验证。本节不再重讲原理，只给属性速查。

长这样： 复印机——第 4 章 4.3 全讲过：<Defines> 里用 <Define id="样板名"> 画样板，哪屏要就在哪屏 <Include ref="样板名" id="复印件名"> 印一份；样板上留的 {{空}} 在引用时逐个填值。

照抄能跑： 与 4.3 示意同一份（据语法拼，非成品，先副本验证）：

<!-- 图纸开头先画样板 -->
<Defines>
    <Define id="navbar">
        <Text textValue="{{title}}">
            <Layout centerX="parent.centerX" top="parent.top+12" width="auto" height="auto"/>
        </Text>
    </Define>
</Defines>

<!-- 哪一屏要，复印一次并填空 -->
<Include id="nav" ref="navbar" title="专辑">
    <Layout left="parent.left" top="parent.top" right="parent.right" height="56"/>
</Include>

常用属性（复印机自己的固定属性只有下面 3 个）：

属性 怎么写 大白话作用
ref ref="navbar" 复印哪份样板（<Define> 的名字）；拼错直接报错挂整屏
id id="nav" 必需，这次复印件的名字；复印件内部组件从此叫 nav/内部名（4.3 讲过）
zOrder zOrder="2" 这份复印件的叠放次序
更多属性： 除了这 3 个，<Include> 标签上再写的任何属性都不算自己的配置，而是给样板填空的参数——样板里 {{title}} 这样一个空，引用时写 title="要填的值" 补上；哪些空能填、叫什么名，全看那份 <Define> 自己留了什么（所以没有固定清单）。填空只准进"显示类"属性，onClick / subscribe 里不许用（规矩明细见 4.3）。

小白坑： id 或 ref 缺一个、样板名拼错、留的空没填齐——都是报错挂掉整屏，没有"半显示"的余地。另外别忘了 4.3 的排他条款：抽屉（Stack）队里不许放 Include（和 Box/Stack 同罪，整屏挂掉）。

5.4 播放与视觉

本节 10 张卡，分两堆：前四个（Visual、SpectrumView、CoverFlow、VinylTurntable）是播放页的"主体展示"——可视化画面、频谱跳条、封面流、黑胶转盘；后六个是歌词家族（LyricShow、KaraokeShow、LyricDisplay、LyricLineShow）加两个功能标签（CountdownView 定时关机列表、PlaybackUiIndicator 顶部三态切换条）。水管（subscribe）大多接的是"该显示时才显示"的显隐牵线，用到的 playback.ui.visualShowing、playback.ui.lyricShowing 这几个数据名第 3 章表里没列，但都是现成图纸实测在用的，照抄即可。有个例外先说在前头：CoverFlow 没有水管。老规矩：每卡"照抄能跑"都带 <Layout/> 小跟班。

5.5 均衡器

本节 4 张卡，拼出"音效-均衡器"那一页。均衡器就是调高低音：整首歌整体调高调低叫"总增益"，把低音、中音、高音分开调叫"分频段"。四个零件各管一块：EQPreamp 是一根总增益竖滑杆、EQBand10 是一排 10 根分频段推子（页面主体）、EQSelectBox 是选预设（流行、摇滚那种）的下拉框、EQMeterChart 是显示各频段当前高低的曲线图。这一节有个和前几节都不同的关键点：这四样都不接水管、不写命令——滑杆的数值、预设列表、曲线画法全是 App 内部自动喂好的，图纸只管"摆哪、长啥样、穿什么图"。页面顶上的开关、保存、重置用的是普通的 ToggleButton / Button（5.2 教过），喊的命令词真实存在于图纸：equalizer-switch-toggle、equalizer-preset-save、equalizer-preset-reset（CoverFlow 图纸第 1568、1604、1594 行）。四张卡的活例子全部出自 CoverFlow 图纸第 1560~1659 行的均衡器页——这是均衡器组件用得最全的主题；Simple、Black、Vinyl 的同款页面写法几乎一样。老规矩：每卡"照抄能跑"都带 <Layout/> 小跟班。

5.6 列表与页面级

这一节的 18 张卡都是一整屏或一大块整列表的组件：App 的主要界面——歌曲列表、资料库菜单、设置页、主题选择页——全由这一族的标签撑起来。它们和前面几节的卡有个大不同：标签自己身上几乎没属性（大多只有 id zOrder insets 三个，少数多两个 cellHeight lineSpacing，个别多几个颜色/图属性），真正决定"每一行长什么样"的内容全部写在子标签里——<Table> + <Cell>（列表行样式）、<Grid>（网格样式）、<Items>（菜单项）、<Settings>（设置分组和开关）、<EmptyView>（空页提示）、<ContextMenu>（长按菜单）。这些子标签本书没逐一开卡，所以这一节的正确用法是：整段抄现成主题的写法，只改值、不动结构；想大改样式，就对照每张卡"更多属性"里给的行号，把子标签一起看懂再动手。

每张卡的"常用属性"表只列标签自己身上真正生效的几项（已逐个核对引擎源码），子标签里的样式属性一概不往标签身上搬——这是 5.4 定时关机、5.5 均衡器反复强调的老教训，在这一族里最容易翻车，也最要紧。

行号出处说明：本节除注明外全部取自 Simple 主题的中文版图纸 Simple/theme.zh-Hans.xml（图纸骨架和默认的 theme.xml 一致，只是文字是中文，更好认）。<Layout/> 小跟班张张都带，规矩同 1.4。

第 6 章 图片怎么准备

前面每章的卡片里反复出现过 ePlay、eAlbumCover 这样的图片名。这一章把图片这件事讲全：放哪、怎么起名、图纸里怎么引用、格式选什么、以及新手最容易踩的几个坑。

6.1 图片放哪

第 2 章说过，一个主题就是一个收纳盒（文件夹）。图片就放进这个盒子里，和图纸（theme.xml）同一层。比如 Simple 主题里的播放按钮，完整路径是 AMPod/Themes/Simple/ePlay@3x.png。

引擎装载一个主题时，只在这个盒子里找图。图片放到别处（桌面、盒子里再套的子文件夹）都不算数——图纸里名字写对了也永远找不到。

6.2 名字怎么起

一张图的全名长这样：eFavMark@3x.png。拆开是四段：

段 例 是什么
前缀 e 小写字母 e。AMPod 现成主题的零件图几乎都以它开头（可记成"图元"的 e，唯一例外下面讲），照这个传统来，别"创新"换别的字母
意思 FavMark 这张图是干什么的，驼峰拼法（每个单词首字母大写，连成一串；"收藏标记"）
清晰度 @3x iOS 的屏幕清晰度档位，见下
格式 .png 图片格式，见 6.4
@2x / @3x 是什么： iOS 的屏幕有"粗"有"细"（老屏一个像素点大、新视网膜屏一个像素点小得多），同一张图按精细度出成不同"档位"是 iOS 的老传统，@2x、@3x 就是两档标记。在这套主题引擎里，图纸写基名后引擎自动补档位找图：先找 @3x 那张，没有再找 @2x（顺序固定，跟设备型号无关）。所以新手只要出一档、出 @3x 就够——Simple 的 110 张图实测全部只带一个档位后缀（86 张 @3x、24 张 @2x），没有一张同时出两档，也没有一张不带后缀。

"全都以 e 开头"有没有例外？ 有一个：Snapshot@2x.png——主题选择页的缩略图（5.6 主题清单卡说过它是约定名）。它是给"整个盒子"拍的照片，不是界面零件图，所以不遵守 e 前缀。除此之外的图，照 e 前缀走就对了。

意思那段怎么拼没有硬性规定： 有完整短语（eContextMoveToFolder，长按菜单里"移到文件夹"的图），也有缩写（eLrcSearch）。拿不准就翻现成主题的图，见样学样。

6.3 图纸（XML）里怎么引用

一句话规矩：只写基名——不带 .png，也不带 @2x/@3x。 下面每条都是 Simple 图纸里逐字能查到的真实写法：

引用写法 用在哪
icon="eAlbums" 底部标签页的图标（图纸第 750 行）
imageNormal="ePlay" 按钮的常态图（5.2 IconButton，图纸第 1151 行）
image="eIconRight" 单独摆的一张图（5.1 Icon，图纸第 1639 行）
defaultImage="eAlbumCover" 图片占位——封面还没来时先垫它（5.1 Image，图纸第 1070 行）
coverOpIcon="eCoverEdit" 封面角上"换封面"的小图标（5.6 ID3TagView，图纸第 1060 行）
imageChecked="eChecked" 网格里格子选中时的勾图（5.6 Grid，图纸第 1584 行）
规矩的反面：引擎其实"宽容"——imageNormal="ePlay.png"、imageNormal="ePlay@3x" 这类带后缀的写法，它兜一圈也能找回来。但别依赖这份宽容：现成图纸几千行全是基名写法（上面表格就是证据），跟着写最稳；而有些档位写法是真坑，比如图纸写 ePlay@2x、盒子里却只有 @3x 图——引擎指定档位时就不再退档，结果图不显示、也不报错（和 5.1 Icon 卡的小白坑同一个）。矩形板铺图用的 fillImage="某图名" 也一样写基名。

一个特殊引用： 图纸里偶尔见到 defaultImage="context:app.icon" 这样的写法——冒号开头的 context: 不是文件名，别去文件夹里找这个 png。它走的是第 3 章讲的"水管"：数据由程序当场递过来（这里是 App 自己的图标），跟磁盘上的图片文件没关系。

6.4 格式与透明

  • 用 .png，别用 jpg。 PNG 支持"透明通道"——图上没画的地方是真正透空的，能透出底下的东西；jpg 不支持，硬存会给你垫一层白底。
  • 为什么透明重要： 主题有深色有浅色，透明底的图标摆在什么颜色上都只有图案本身、四周不会顶出一块"白边"。第 1 章讲过组件像透明贴纸一样叠放（zOrder），图也是——透明才能叠得干净。
  • 分工： 小图标（按钮、箭头、勾选这类）一般做成透明底、单色图案，跟各种主题配色都不打架；大图（专辑封面、背景、唱片盘面）可以全彩、不透明，没有特殊要求。

6.5 加自己的图、改现成的图

加一张新图，两步：

  1. 按 6.2 的规矩做好图，比如 eMyButton@3x.png，放进你的主题文件夹，和 theme.xml 同层；
  2. 在图纸里按 6.3 的规矩引用基名，比如 <IconButton imageNormal="eMyButton" ...>。
改一张现成图： 把你做好的新图同名覆盖进主题文件夹里那张（建议先把原图拷一份留备份）。文件名对上就生效，图纸一个字都不用改。

6.6 小白坑汇总

  • 引用名和盒子里的图对不上：图纸写 imageNormal="ePlay@2x" 可盒子里只有 ePlay@3x.png（指定了档位，引擎就不退档了）→ 图不显示、不报错。写基名 ePlay 让引擎自己挑档位，正是躲开这个坑的正规姿势。本章头号坑。
  • 只出了 @2x、没出 @3x：写基名时引擎按 @3x → @2x 的顺序找，只有 @2x 图也能显示，但精细屏上是把 @2x 图放大凑合，画面发糊。只打算出一档的话，出 @3x。
  • 大小写不一致：文件叫 EPlay@3x.png，图纸里写 ePlay → 找不到。iOS 文件系统分大小写，e 和 E 是两张不同的图。
  • 用中文、空格、连字符起名：我的按钮@3x.png、my button-1.png → 别这样，照 e驼峰 的现成规矩来。
  • 图放进了子文件夹：引擎不往子文件夹里看。和图纸同层，一个盒子里平铺（6.1）。

B.2 第一次改：把播放页的封面变大

  1. 用文本编辑器打开 AMPod/Themes/MySimple/theme.zh-Hans.xml。
为什么不是 theme.xml？2.3 讲过"点餐"规则：手机语言是简体中文时，App 点的是 theme.zh-Hans 系列这张，theme.xml 只是兜底款。想双保险，就两个文件做一样的改动（它们骨架相同）。本章练习先只动这一两个，正式改主题要 54 个变体同步改，2.3 说过。
  1. 找到播放那一屏：搜 <Page id="Playback">，在 theme.zh-Hans.xml 第 1066 行。
  2. 在这一屏里找封面：搜 id="albumCover"，会找到第 1070~1075 行这块 <Image>（注意：图纸里 albumCover 这个名字出现好几处——迷你条 34 行也有一枚，别改错；本页认准 1070 行往下的，它在 <Scroll> 相册的第一个 <Box> 里）。它的 <Layout>（第 1073 行）原样是：
<Layout top="parent.top+48" left="parent.left+32" right="parent.right-32" height="#albumCover.width@999"/>
  1. 把 left="parent.left+32" 和 right="parent.right-32" 里的 32 都改成 12，改完后整行是：
<Layout top="parent.top+48" left="parent.left+12" right="parent.right-12" height="#albumCover.width@999"/>

效果：封面左右各少让 20，整张宽出 40；height="#albumCover.width@999" 那句是第 4 章讲过的"正方形跟宽度走"，高度自己跟上，不用你动。保存文件。

B.3 第二次改：换个歌名颜色

  1. 还在 theme.zh-Hans.xml，搜 id="textTitle"，找到第 1078 行那一块——它是播放页的歌名，身上绑着 subscribe="text:${media.title}"（第 3 章的水管）。
  2. 把它身上的 textColor="#e0e0e0" 改成 textColor="#ff5252"（醒目的红；# 后六位红绿蓝各两位，想换别的色自己调）。
  3. 保存。注意：图纸里 textColor="#e0e0e0" 出现很多次，别用批量替换——一定要按 id="textTitle" 搜到那一行再改，不然会把别的屏的字一起染了。

B.4 第三次改：换底部第一个标签的图标

  1. 搜 eTabMedias，在 theme.zh-Hans.xml 第 22 行：<Medias icon="eTabMedias"/>——底部标签栏"媒体"那格用的图。
  2. 把它改成 icon="eAlbums"：MySimple 文件夹里就躺着 eAlbums@3x.png，名字照 6.3 的规矩不带 .png、不带 @3x。
  3. 保存。想换别的，在 MySimple 文件夹里看还有哪张 e* 图顺眼，就填它的基名。

B.5 在 App 里切到 MySimple，看效果

（改完文件要先像 2.4 那样把 MySimple 放进工程、重新编译安装，App 里才会认得这个新主题。）

  1. 打开 App → 底部"更多" → 点"主题" → 在网格里选中 MySimple。
  2. 随便播一首歌，点屏幕底部的迷你播放条，展开完整播放页，逐条对照：
- 封面是不是变宽变大了？ - 歌名是不是变红了？ - 屏幕底部第一个标签的图标，是不是从"媒体"换成了"专辑"那张图？

三处都变了——你已经第一次亲手改出一个主题了。只有部分生效？说明那几处改动你漏了某一步，或改到了别的文件——回 B.2~B.4 逐个对一遍。

下面每条排错前先记住：本附录的行号以刚复制好、还一个字没改过的 MySimple 为准；你每改一行，后面的行号就可能挪一两行，所以每次都是"先搜、再改"最保险。

B.6 没看到效果？排错三步

  • 整个界面一点没变：十有八九是没切到 MySimple（回到 B.5 第 1 步）；如果已经切了还是没变，多半是你手机命中了"尺寸专款"图纸（2.3 的点餐规则，比如 theme.zh-Hans@375x667.xml），把 B.2~B.4 的三处改动原样再做进那个尺寸文件里。
  • 某一屏变空白、或整个界面退回没改的样子：XML 某处写坏了——最常见是标签没闭合、< 或 > 少一个、引号漏了一边（2.5 讲过）。撤销你刚才改的那一小处，保存重进，看回没回得来；回来了就说明病根确实在那一行，逐字符检查再改一遍。
  • 封面大了但歌名颜色没变（或反之）：你改的两处不在同一屏，或者搜 textColor 时改到了别的 <Page> 里的字——第 2 章 2.2 讲过一屏一段，按 id="textTitle" 重新定位到 Playback 页那处再改。

B.7 下一步

三处改动跑通之后，回到第 5 章，挑一两张卡片里"照抄能跑"的片段，塞进 MySimple 某个 <Page> 里玩：加一个 e* 图名前先确认文件夹里有那张图（5.1 Icon 的小白坑），改完一次只看一屏（2.5 的节奏）。等玩顺手了，再按 2.3 的规则把正式改动同步到全部语言、尺寸变体文件，把你的主题变成"正经主题"。
